# /hdd:audit — 既存チケットの仮説監査

「$ARGUMENTS」（省略時は open な issue 全件）を対象に、各チケットを仮説チェックリストで採点し、仮説が欠落しているものを優先度順にレポートします。

## Step 1: 対象チケットの取得

`docs/hypotheses/README.md` の設定、または実行時の検出でトラッカー種別を確認し、対象を取得する。

- **GitHub Issues**: `gh issue list --state open --json number,title,body,labels,milestone,updatedAt` 等（$ARGUMENTS でラベル・マイルストーンが指定されていればフィルタを付与する）
- **MCP ツール**: 検出済みの issue/backlog 系 MCP ツールの一覧取得系ツールを使う
- **markdown フォールバック**: `docs/hypotheses/` 配下の各ファイルを対象にする

## Step 2: 並列化の判断

取得件数が **20 件を超える場合**、Agent ツールで採点作業をサブエージェントに分割する。

- 目安: 1 サブエージェントあたり 10〜15 件程度のバッチに分割する
- 各サブエージェントには「このチェックリストで各チケットを採点し、ランクと該当項目数、欠落項目を表形式で返す」という自己完結した指示を渡す（親セッションの会話文脈は渡らないため、Step 3 のチェックリストと採点基準を毎回フルで含める）
- 全サブエージェントの結果を回収してから Step 4 のレポートに統合する
- 20 件以下なら通常通りこのセッション内で順に採点する

## Step 3: 仮説チェックリストによる採点

各チケットについて、以下 6 項目への該当有無を判定する。

- [ ] 誰のどんな課題か明文化されている
- [ ] 課題の根拠（観測された事実）が書かれている
- [ ] 成功指標と目標値がある
- [ ] 検証方法と成功基準・撤退基準がある
- [ ] 計測手段が存在する（なければ計測整備タスクを先行させる）
- [ ] 「このタスクをやらない場合に失うもの」が書かれている

該当数に応じてランク付けする。

| ランク | 基準 |
|---|---|
| A | 5〜6 項目該当。仮説と検証計画がおおむね揃っている |
| B | 2〜4 項目該当。仮説の言及はあるが検証計画・根拠が弱い |
| C | 0〜1 項目該当。仮説がほぼ無いまま作られたチケット |

バグ修正・明確な技術タスクと判断できるチケットは採点対象から外し、レポートの末尾に「対象外（バグ修正等）」として件数のみ記載する。

## Step 4: レポート出力

表形式で出力する。C ランクを優先度順（下記ヒューリスティック）に並べ、先頭に置く。

優先度ヒューリスティック（上から優先して判定）:
1. `priority: high` 等の優先度ラベルが付いている
2. マイルストーン期限が近い
3. 直近更新日が新しい（着手が近いと推定できる）
4. 上記が無ければチケット番号が新しい順

```markdown
## 仮説監査レポート（対象: <件数> 件）

| ランク | 件数 |
|---|---|
| A | <n> |
| B | <n> |
| C | <n> |
| 対象外（バグ修正等） | <n> |

### C ランク（優先度順）

| # | チケット | ランク | 該当数 | 主な欠落項目 |
|---|---|---|---|---|
| 1 | #123 タイトル | C | 1/6 | 課題の根拠, 成功指標, 検証方法, 計測手段, 機会損失 |

### B ランク

| # | チケット | ランク | 該当数 | 主な欠落項目 |
|---|---|---|---|---|
```

## Step 5: C ランク上位への仮説ドラフト提案

C ランク上位（目安: 上位 5 件、対象が少なければ全件）について、チケットのタイトル・本文から推測できる範囲で仮説ドラフト（`${CLAUDE_PLUGIN_ROOT}/templates/hypothesis.md` 形式の簡易版）を生成する。推測に頼った箇所は「要確認」と明記する。

AskUserQuestion ツールで、追記方法を選ばせる。

1. **一括追記** — 生成したドラフトを対象チケット本文に一括で追記する
2. **個別選択** — 1 件ずつ内容を確認しながら追記するか決める
3. **提案のみ（追記しない）** — レポートとドラフトを提示するだけで終える

## 完了報告フォーマット

```markdown
## 仮説監査完了

- 対象: <件数> 件（A: n / B: n / C: n / 対象外: n）
- 追記: <n 件に仮説ドラフトを追記 | 提案のみ>

### 次のステップ
- 個別に詰めるなら該当チケットで `/hdd:grill`
- 定点観測は `/hdd:status`
```
