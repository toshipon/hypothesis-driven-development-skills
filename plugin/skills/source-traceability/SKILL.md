# Source Traceability — 出典トレーサビリティ

調査ドキュメントに書かれた数値・条文・制度・事実は、**どの出典から来たか後から辿れる**状態でなければ資産にならない。二次情報だけを根拠に判定やデータベースを作ると、そのまま顧客に誤情報を出す（実プロジェクトで誤り 4 件を実証済み）。

## ルール

### 1. 出典は sources.md に集約する

ドキュメントごとに URL を散らばらせず、対象ディレクトリ直下の `sources.md` に一覧化する。本文からは `[S1]` `[M2]` のような番号で参照する。

### 2. 一次情報と二次情報を分ける

| 区分 | ID 接頭辞 | 定義 | 例 |
|---|---|---|---|
| 一次情報 | `S` | 官公庁・当事者の発表、原文・原データ | 省庁の報道発表 PDF、法令原文、当事者 PR、公式統計 |
| 二次情報 | `M` | 第三者による解説・報道・ブログ | 業界メディア、解説記事、比較サイト |

- 二次情報は**一次情報で裏取りできるまで「要確認」扱い**とする。裏取り予定を「S5 で裏取り要」のように明記する
- ベンダー自身による競合比較は信頼度「低」から始める

### 3. 表の形式

```markdown
## 一次情報（官公庁・当事者）

| ID | 出典 | 内容 | 確認日 |
|---|---|---|---|
| S1 | [タイトル + 発行日](URL) | 要点。原文を取得済みなら **原文取得・読了済** と保存先を書く | YYYY-MM-DD |

## 二次情報（メディア・ブログ）

| ID | 出典 | 内容 | 信頼度 |
|---|---|---|---|
| M1 | [タイトル](URL) | 要点 | 高 / 中 / 低 — 理由 1 語 |

## 未取得・要取得

- [ ] <取りに行くべき一次資料と入手方法>
```

### 4. 本文の書き方

- 数値・条文・制度に言及する文には必ず出典番号を付ける: 「届出住宅 42,070 件 [S5]」
- 出典番号を付けられない記述は**憶測**である。憶測を書くなら「推定」「未確認」と明示する（→ `graded-assertions` skill）
- 日付は必ず絶対日付（YYYY-MM-DD）。「先月」「来週」「半年後」を書かない
- リンク切れに備え、判定の根拠になる一次資料（PDF 等）はリポジトリ内に取得保存し、保存先を sources.md に書く

### 5. 更新時

- 既存の記述を書き換えるときは、新しい出典を追加してから本文を直す。出典なしの上書きをしない
- 「未取得・要取得」リストを維持し、取得したら一次情報の表に昇格させる

## チェックリスト（ドキュメント完成前）

- [ ] 数値・条文・制度の記述すべてに `[S_]` / `[M_]` が付いているか
- [ ] `[M_]` のみを根拠にした断定がないか（あれば「要確認」へ）
- [ ] 相対日付が残っていないか
- [ ] 未取得の一次資料がリスト化されているか
